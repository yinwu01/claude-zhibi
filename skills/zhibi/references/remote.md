# VPS 检查、部署与验证

## 首次连接

1. 在用户电脑执行 `doctor --route web` 或 `doctor --route remote`。如果没有 `ssh`，先按电脑系统启用 OpenSSH。`doctor` 只检查本机工具和平台，远端是否连通以实际 SSH 为准。
2. 从 VPS 控制台核对地址、登录用户名、端口和主机公钥指纹。已有可用的 SSH 别名时，准备对应的私人配置文件路径。知彼读取显式提供的配置；除非用户明确指定，用户名和端口沿用配置。确认跳板及其主机公钥也可信。
3. 首次连接用本机终端交互式登录。按服务器管理方式添加**公钥**或在控制台导入公钥。初始密码只在终端或供应商控制台输入，私钥始终留在本机。看到首次连接的主机指纹时，与可信来源逐字核对后再登记。如果指纹已变更，先核对原因和新指纹。
4. 用同一个 SSH 配置、别名、用户、端口和密钥运行知彼 `check`。能无提示完成此检查后才交付后台服务。后台服务用户需要能在其实际运行环境使用这份认证。依赖当前终端的临时 SSH agent 时，还要在后台服务环境验证一次。

首次核对指纹用下面对应的一条，在自己的终端执行，替换占位符。显示的指纹与第 2 步一致，再确认。

```bash
# 用服务器地址
ssh -o StrictHostKeyChecking=ask -p PORT USER@HOST
# 用已有的私人 SSH 配置和别名
ssh -F PRIVATE_SSH_CONFIG -o StrictHostKeyChecking=ask SSH_ALIAS
```

新生成的后台连接要求已经信任主机公钥。旧版已安装的 launchd 或 systemd 服务仍使用它保存的命令，按 [浏览器后台连接](runtime.md#浏览器后台连接) 重新导出并更新。

## 检查与部署

`check --host HOST --egress` 读取系统、资源、时钟、DNS 配置和网络出口。公共 DNS、UTC 或数据中心标签只作背景；不能据此推断账号风险。网络查询需在本次授权范围内。

先按 [runtime](runtime.md) 判断命令适合交互、一次性还是常驻运行。根据系统和现状准备依赖，安装后验证版本与实际启动。缺少 systemd 时可选择用户已有的其他托管工具，明确当前内置适配器仅支持 systemd。

`build` 默认给出计划；`--apply` 保存私人原值与执行回执。对同名服务，内置脚本拒绝符号链接、厂商 unit 和 drop-in，避免覆盖其他配置。替换普通 unit 前备份并记录原启用/运行状态，语法验证后启动，失败尝试恢复。

进程 active 和 enabled 分别说明当前运行与开机自起，均不证明应用健康。检查日志和实际应用操作；时区/语言仅按用户选择调整。当前 locale 步骤只是生成语言资源，不能声称已经改变所有登录会话的默认语言。

连接中断后先核对部署回执、服务和原值，不假定整体成功或自动重跑。恢复命令使用回执中的远端路径；保留回执直到用户确认本轮结果。
