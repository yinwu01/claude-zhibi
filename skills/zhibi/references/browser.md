# 浏览器接入

交付目标：用户在自己选用的指纹浏览器中直接打开已配置的环境，就能使用目标服务。知彼负责首次配置与维护，不成为日常启动入口。

Agent 按品牌、版本、现有权限和工具能力选择 API、computer use 或两者结合。已有可用且足以完成任务的 API 时优先使用，缺少 API 或能力不足时操作实际界面；不写死菜单路径、控件名称或固定品牌，也不要求用户准备 API Key。用户已有合适环境就复用，否则在授权范围内建立专用环境，避免影响正在使用的其他环境。API 是可选执行方式，不是接入前提。

根据已准备好的稳定线路，保存该环境的代理及所需 DNS、WebRTC、IPv6、时区和语言设置。配置前记录原值；只修改与目标有关的项目，不为了形式一致机械照抄服务器设置。浏览器与代理必须实际连通：回环地址只适用于同一台机器，代理协议按客户端能力选择。需要本机隧道时，应先由 Agent 配好后台连接，让用户不必保持终端窗口。

保存后，在同一浏览器环境中打开目标服务并用 session 核对实际出口；在不影响现有工作的情况下关闭重开，确认设置仍生效。仅保存设置不算验收，未测项如实记录。账号登录由用户完成。交付时说明以后打开哪个环境，以及需要撤销时如何恢复；日常关闭浏览器不必撤销已保存的配置。

API 和 computer use 都无法完成的必要步骤才交给用户，再继续核验；不要求用户为了接入而购买 API 权限。

## 创建专用 Chromium 配置

用户选择直接启动 Chromium 系浏览器时，用 `browser-workspace --browser-binary 可执行文件 --local-port 10818 --out 新目录` 创建独立环境。默认不导入历史、Cookie 或扩展；限制定位、摄像头、麦克风和通知，关闭扩展与同步，设置 SOCKS5 和 WebRTC 非代理 UDP 限制。运行生成的 start-browser.py 后再执行 session。需要通话/录音/定位时，按目标站点实际用途允许权限并复测。

该入口不编辑 AdsPower 等管理器的内部配置；已有指纹环境由 Agent 通过可用 API 或 computer use 设置同等控制。四项权限在真实 Chrome 上使用页面权限查询进行验证，其他衍生浏览器仍需同样读回。
