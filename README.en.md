# claude-zhibi · 知彼

Zhibi is an Agent Skill that helps developers inspect and set up a dedicated environment for Claude. Use a separate browser profile for the web app and an isolated Linux workspace for Claude Code. The agent measures the actual network path for each environment.

**Choose how you want to use Claude**

- [Web only](#route-a-claude-on-the-web) · Set up a dedicated browser and open it directly for daily use.
- [Web and Claude Code](#route-b-web-and-claude-code) · Reuse your Linux VPS where possible and open the configured project from your computer.

[简体中文](README.md) · [Get started](#get-started) · [Implementation status](docs/implementation/two-route-plan.md)

IPv6 is disabled by default in managed PVM guests; the private proxy gateway permits IPv4 egress only. Host networking is unchanged.

The `claude-zhibi` project uses the name `zhibi` for its CLI, Skill, and Python package.

## Two runtime routes

| Route | Application runtime | Files and browser |
| --- | --- | --- |
| Web only | Your own VPS provides the browser's network route over SSH | A separate profile in your browser, with a connection service on macOS or Linux |
| Web and Claude Code: remote Linux | A dedicated Linux workspace with an isolated application entry point and a private gateway | The browser and CLI can share the gateway. The VPS can also serve as the Linux work machine |
| Web and Claude Code: local Linux VM | A PVM-managed Ubuntu guest on Apple silicon macOS or Linux amd64, or an existing VM over SSH | Keep the project on your computer. A managed VM can use the host connection with `--exit direct`, or a separately configured remote exit |

Runtime location and network exit are separate choices. PVM supports a registered VPS exit and an explicit `direct` mode. The private VPS gateway can also use a user-supplied SOCKS5 upstream. The selected upstream must be available for requests to proceed. [Runtime setup](skills/zhibi/references/runtime.md)

Use a server you control for the VPS route. You can check an existing environment without a VPS. Use the official account flows for sign-up, billing and verification, and check the service's eligibility requirements before using it. [Anthropic Supported Regions Policy](https://www.anthropic.com/legal/supported-regions)

## What you receive

- A dedicated application environment and a corresponding browser setup.
- Private project bindings with start and optional application-specific resume commands.
- Explicit uploads/downloads for the remote route, or a shared project for local VMs.
- A report that compares the browser and its reference route side by side, with separate IPv4, IPv6, WebRTC and DNS readings where available. Rechecking can also show changes since handover. [Acceptance procedure](skills/zhibi/references/audit.md#出口一致性)
- Instructions to stop, restore and remove the configuration you created.

A smaller environment helps align the chosen timezone, language and network path while limiting exposure of unrelated home directories, settings, extensions and permissions. Chromium workspaces generated by Zhibi use a separate profile and restrict selected permissions, extensions and sync. Other browsers need their own supported API or UI configuration and verification.

## Get started

Use Python 3.9+, an SSH client and an Agent host such as Codex. Computer use is helpful for browser settings; supported APIs and manual steps can also be used.

```bash
git clone https://github.com/yinwu01/claude-zhibi.git
cd claude-zhibi
python3 scripts/install_skill.py --host codex
```

Add `--replace` to upgrade an existing install. The installer keeps the previous version and prints the rollback command.

In a new agent session, start with:

> Use $zhibi to get me started from where I am now.

The agent asks what you want to do, what account steps you've completed, and whether you have a VPS if your setup needs one. It can guide you through official account and subscription screens with computer use. You handle passwords, verification, and payment confirmation. [Google Play subscription guide in Chinese](docs/tutorials/claude-google-play.md)

For a VPS setup, have its address, SSH user and port (or your existing SSH alias and config file), and a host key fingerprint you can verify through a trusted channel such as the provider console. If you only have an initial password, start with an interactive login in your own terminal and set up a public key. The agent checks that the same SSH target works without a prompt before installing the background connection. [First connection guide in Chinese](skills/zhibi/references/remote.md#首次连接)

### Route A: Claude on the web

> Use $zhibi to inspect my browser and VPS. Set up a dedicated browser profile and test its connection with a test page. Tell me which profile to open and how to restore the setup.

### Route B: Web and Claude Code

> Use $zhibi to inspect my browser and VPS. Set up an isolated workspace on my Linux VPS and connect the browser to the same private gateway. Verify the setup with a synthetic command and tell me how to open the configured project.

If you have no Linux server, use PVM to create a local VM or attach an existing Linux VM. With no VPS, a managed VM can use your computer's network with `--exit direct`. Configure a VPS separately if you need a dedicated remote exit. [Local VM setup and supported platforms](skills/zhibi/references/local-vm.md)

## Daily use

Open the dedicated browser profile for web use. The handover includes `open-browser.sh` for a generated Chromium workspace, or `open-vm-desktop.sh` for a profile inside PVM. For a bound CLI project, run `open-project.sh` in a terminal on your computer. You can also use the verified shell entry from the configured project directory on remote Linux. The browser connection attempts to reconnect automatically. Recheck the measured exit after changing lines or if access does not recover.

For a bound SSH project, `zhibi project editor --out PRIVATE_DIRECTORY` exports a separate SSH profile, editor settings and a terminal launcher. Editor extensions and the real deployment need their own verification. [Editor setup](skills/zhibi/references/projects.md)

Project bindings remain available for managing and restoring a launch, including on the local VM route:

```bash
zhibi project status
zhibi project start --apply
# Only when the application supports it and a resume script was configured
zhibi project resume --apply
```

Skill-only users replace `zhibi` with `python3 ~/.agents/skills/zhibi/scripts/zhibi.py`. To install the standalone CLI from the checkout, use `python3 -m pip install .`.

Remote transfers require existing parent directories and never overwrite destination files:

```bash
zhibi project upload --local ./image.png --remote-file uploads/image.png --apply
zhibi project download --remote-file reports/result.txt --local ./result.txt --apply
```

Local VM controls:

```bash
zhibi vm status --workspace VM_WORKSPACE --live
zhibi vm desktop --workspace VM_WORKSPACE --apply
zhibi vm stop --workspace VM_WORKSPACE --apply
```

Application login and history persist in the runtime environment. Session restoration uses the application's own protocol; it is not background process supervision. Use the remote `runtime-service` workflow for persistent services. Local VM tasks stop when the host is shut down.

## Verification and privacy

`project audit` measures the selected execution environment, compares an imported browser observation and can run a controlled disconnect/reconnect drill. For an SSH project, `project bind --runtime-workspace` makes startup, resume and measurement use one process workspace. `deliver --outage-report REPORT` carries a recent drill result into the handover. `reproduce.sh` compares new readings against the handover baseline. A fixed exit change fails that check; a dynamic exit change is flagged for review. Use `environment status --folder DIR` to resume from a private workflow or delivery folder.

Missing observations remain unmeasured. The actual browser, application session and protocol behavior each need their own evidence. See the [current implementation and acceptance record](docs/implementation/two-route-plan.md) and [persistent entry status](docs/implementation/native-delivery.md).

Reports and private configuration are processed locally. Network probes and optional IP-information lookups still contact their stated services, which can see the request IP or queried IP. Zhibi does not collect browser cookies or account credentials. [Data flow](docs/reference/privacy.md).
